# مختبر 2 — عقد المجالات والمراحل

تُقرأ هذه الصفحة مع data-contract.md. أساس HTML/CSS والشاشات وpatches يبقى كما
هو؛ الشاشة الآن قد تكون مخططًا، storyboard، شرحًا بصريًا أو خطة، وليست موقعًا فقط.

صيغة البيانات `version: 2`. تضيف:

- `domain`: أحد `interface`, `motion`, `video`, `planning`, `explanation`, `mixed`.
- `phases`: مصفوفة `{id,title,description}` تُرتّب المراحل، بلا مراحل فارغة.
- `deliverables`: قائمة نصوص بالمخرجات المطلوبة.
- `workItems`: عناصر `{id,title,phase,description,dependsOn:[id],acceptance}`.
  المراحل موجودة، والاعتمادات موجودة وغير دائرية. هذه مهام تنفيذ لا أسماء مبهمة.
  تقبل `when` بشروط على قرارات موجودة. المهام العامة محايدة بين الخيارات؛ المهمة
  التي تفترض قرارًا معينًا يجب أن تكون مشروطة أو خاصة بالبديل.
- `viewports`: اختياري، مثل `[{id:'mobile',title:'جوال',width:390,height:780},
  {id:'desktop',title:'كمبيوتر',width:1280,height:800}]`. للفيديو استخدم `portrait`
  540×960 و`landscape` 1280×720 و`square` 800×800؛ للخطة استخدم `board` و`compact`.
- `motionDuration`: مدة تشغيل المعاينة بالمللي ثانية، اختياري 1600–30000.

كل سؤال يضيف:

- `phase`: id المرحلة.
- `presentation`: `cards`, `gallery`, `comparison`, `storyboard`, `timeline`,
  `diagram`. **نوّعها حسب القرار**؛ ليس مطلوبًا استخدام كل نوع في كل عمل.
- `recommendation`: تعليل الافتراض المقترح حسب الهدف والقيود، لا «الأفضل» مطلقًا.
- `impact`: ما الذي سيتغير في النتيجة بسبب هذا القرار.
- `when`: اختياري `{questionId: ['optionId', ...]}`. كل الشروط AND، والبدائل
  داخل الشرط OR. يعتمد فقط على أسئلة سابقة، وتظهر متابعة مناسبة للاختيار.
- `allowIdea`: اختياري default true؛ مساحة لفكرة جديدة أو تركيب من بدائل.

كل بديل يحتفظ بالحقول الأصلية، ويضيف:

- `axes`: مصفوفة 2+ محاور يختلف فيها هذا الحل (بنية، ترتيب، مسار، كاميرا، إيقاع،
  تفاعل، توزيع، نوع شرح...). اختلاف اللون أو السرعة وحده غير كافٍ.
- `visual`: `{html,css}` اختياري؛ miniature حقيقي/تخطيطي للفكرة داخل بطاقة الاختيار.
  ليس شعارًا زخرفيًا. يخضع لفحص HTML/CSS، ولا يحتوي inputs أو scripts تفاعلية.
  إن غاب، يستخدم المكوّن preview نفسه. CSS العام وoption.css متاحان له.
- `workItems`: اختياري، مهام تخص هذا البديل وتُدرج فقط عند اختياره. IDs فريدة
  عبر كل المهام، وdependsOn يشير لمهام عامة أو مشترطة مناسبة، لا بديل متعارض.
  المهام غير الفعالة تُستبعد وتُطوى تبعياتها إلى المتطلبات الفعالة السابقة.

مستحسن 20–60 قرارًا مناسبًا للعمل المركّب، موزعة على مراحل، و8–15 للمهام الصغيرة
ذات القرارات الحقيقية. لا تحشُ أسئلة لبلوغ رقم. يوجد حد تنفيذ 200 سؤال لحماية
الملف، وليس هدفًا للوصول إليه. قبل البناء قدّر قرارات العمل وأزل المكررات.
3–8 حلول متمايزة لكل قرار. قارن الفكرة والدور والتقسيم والتفاعل؛ لا تنتج نسخًا
بنفس البنية مع لون مختلف. سؤال رقمي عن مدة مشهد له بدائل إيقاع كاملة (حدث/توقيت/
انتقال)، وليس تغيير الرقم فقط. تفاصيل دقيقة يمكن كتابتها في الملاحظات.

كل سؤال يملك slot مستقلًا؛ فروع السؤال أيضًا تستخدم slots مستقلة.
لا تضع slot داخل slot آخر: patch الأب يحذف محتوى الأبناء. استخدم slots أشقاء.
الأسئلة المخفية لا تُطبّق ولا تُعتمد، لكن الاختيارات والملاحظات تبقى عند العودة.
تُولّد الأسئلة والبدائل مسبقًا بواسطة الوكيل؛ HTML مستقل بلا نموذج يعمل داخله.
بعد جولة، النص النهائي قد يطلب بحثًا أو جولة مختبر أخرى عند وجود قرار غير محسوم.

الحركة تُنفذ CSS وSVG ثابتًا مع CSS animation، لا scripts من بيانات المشروع.
`data-playing=true` على html يشغّل CSS؛ استخدم keyframes مختلفة فعلًا: قطع، pan،
zoom-in، zoom-out، match cut. اجمع المختار في storyboard متسلسل مع أوقات وتوقعات
إنتاج في `implementation`. المعاينة شرح بصري للحركة؛ ليست تصدير MP4 أو renderer فيديو.
الشروح والخطط يجب أن تظهر بنيتها بصريًا (خريطة/خط زمني/جدول/تسلسل) في المعاينة،
لا تُجبرها على هاتف أو بطاقات منتجات.
